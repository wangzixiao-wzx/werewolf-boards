# 狼人杀版型库

一份只读、零依赖的**狼人杀板型（版型）资料库**：把每个板子的身份构成、阵营分布和特殊规则整理成可搜索、可筛选、可复制的清单。开局前选板、给法官发配置、查「某个身份都在哪些板子里出现」都能用。

在线查看：https://wangzixiao-wzx.github.io/werewolf-boards/

> 数据规模：**77 个版型 · 126 个身份 · 421 条特殊规则 · 4 个阵营**
> 其中 **48 个版型**收录于「法官版型清单」（合计 123 场对局），带分类 / 来源判定 / 场次；另 29 个为清单未收录的板子。
> 2026-11-08 第一批补入 28 个版型的技能细则 / 房规 / 行动顺序，并新建 5 个版型（千年之恋、胡夫地平线、灯影预言家、纯白夜影、血月猎魔人）与 3 个身份（白蛇预言家、许仙寻香魅影、阿努比斯）。
> 同日第二批补入 4 段细则：新建 12人阴阳师、12人火力全开 与 阴阳师 / 小精灵 / 恶灵 3 个身份，并为「12人魔幻对决」补齐换号 FAQ、「唯邻是从」补上傀儡不带刀的判定。细则源文本含法官署名与日期，**这些署名不写入数据库、不进入公开快照**。

## 特性

- **全文搜索**：板名、身份名、特殊规则文本一起搜（按 `/` 聚焦搜索框）
- **多维筛选**：人数（6 / 9 / 10 / 12）、含第三方、含变动阵营、有特殊规则、牌数≠座位数
- **版型分类**：网易官方 / 其他版型 / 暂停开放 / 10 人版型 / 未收录清单，另可只看 ★ 新板或仅清单收录；卡片显示场次、来源判定与暂停状态
- **身份反查**：身份索引页点任意身份，直接列出所有使用它的板子
- **详情与复制**：按阵营分组的完整身份表 + 特殊规则全文，一键复制成可发给主持人的配置文本或 JSON
- **随机抽板**：在当前筛选结果里随机抽一个，解决「今天打什么」
- **牌数 ≠ 座位数**：盗贼 / 丘比特 / 双身份这类多牌板会单独标注，不会被当成数据错误
- 单文件前端 + 静态数据，双击 `index.html` 即可离线使用，无需服务器、无需构建

## 目录

| 文件 | 用途 |

## 数据说明

数据来源是自建的狼人杀对局数据库，但**导出时只读取 `board` / `board_role` / `board_rule` / `role` / `faction` 五张配置表，以及 `board_meta` 清单元数据表**，从不读取 `game` / `game_player` / `player` / `player_alias` 等对局与玩家表。

「法官版型清单」是对一批对局文本按板子归类的整理稿，提供分类、来源判定与场次统计。`board_meta` 由 `werewolf-stats/apply_board_catalog.py` 写入主库（写前自动备份）；其中 `doc_files`（对局文件名单）与 `doc_roles`（清单原始配置文本）**只存本地库，导出脚本明确不读取、不导出**。

因此仓库中**不含任何玩家昵称、对局记录、对局文件名、战绩、法官姓名或游戏时间**，只公示场次数字，可以安全公开。这一点由导出脚本的读取范围与校验保证，而不是靠事后过滤。

字段含义：

- `seats`：座位数；`card_count`：身份牌张数；`multi_card`：两者不等（多牌机制）
- `judge`：法官人数
- `category`：网易官方 / 其他版型 / 暂停开放 / 10 人版型 / 未收录清单
- `origin`：来源判定（网易官方出处 / 网上流传 / 群内自创 / 查无出处）
- `games`：清单统计的对局场次数字（未收录清单时为 0）
- `is_new`：★ 2025—2026 新板；`status`：开放 / 暂停开放；`in_doc`：是否被清单收录
- `cards`：按原板子配置顺序展开的身份牌，含 `role` / `faction_id` / `count`
- `rules`：`key`（规则类别）、`value`（规则正文）、`role`（关联身份，可为空）
- `search`：预拼的检索文本（含分类与来源判定），供前端快速过滤

规则文本来自自建对局复盘整理，各家村规可能不同，实际开局请以主持人口径为准。

## 本地更新

```bash
# 需要 Python 3（仅标准库），数据库默认读取 ../werewolf-stats/werewolf.db
python ../werewolf-stats/apply_board_catalog.py --apply   # 清单有变动时：备份并刷新 board_meta
python export_boards.py                  # 重新生成 data.js / boards.json / BOARDS.md
python export_boards.py --db 别的.db     # 指定数据库
python export_boards.py --check          # 只做一致性校验，不写文件
```

导出会校验每个板子都有身份配置、张数汇总一致、板子 id 不重复、清单收录数与场次数自洽，并额外检查**没有把对局文件名或内部字段带进公开快照**；同时打印「牌数≠座位数」的板子清单。生成后刷新页面即可看到新数据。

> 清单与库内既有板子的角色阵营口径存在少量差异（例如孤独少女的阵营归类、白痴/白神与混子等别名）。`apply_board_catalog.py` 只报告这些差异，**不会自动改写 `board_role`**，以免动到已录入对局的统计口径。

## 部署 / 发布

仓库根目录即静态站点，GitHub Pages 选择 `main` 分支根目录；`.nojekyll` 已放置，避免 Jekyll 处理静态文件。

首次发布或后续更新可用 `publish_github.py`（仅标准库）：

```bash
python publish_github.py --token <GitHub PAT>
# 或者：GITHUB_TOKEN=<GitHub PAT> python publish_github.py
```

脚本走 **GitHub REST API**（不调用 `git push`）：验证 token → 创建或复用仓库 → 把目录内全部文件写成 blob / 目录树 → 创建提交并更新 `main` → 开启 Pages 并等待构建 → 打印在线地址。重复运行是幂等的：远端目录树与本地一致时不会新建提交。token 只通过参数或环境变量传入，不写进仓库文件、remote URL、git config 或日志输出；需要 classic PAT 的 `repo` 权限。

> 为什么不用 `git push`：部分代理 / 受限终端环境下，git 的 HTTPS 传输会挂起或反复索要用户名，而 REST API 通道正常。脚本只在本机执行 `git add` / `commit` 这类纯本地操作，用来保持工作区干净；远端提交由 API 创建，本地与远端的 commit sha 不同是正常的，更新数据请继续用本脚本，不要手动 `git push`。

也可以完全手动：在仓库 Settings → Pages 里选 `main / root`，文件用网页上传或普通 git 推送均可（若你的网络允许）。
